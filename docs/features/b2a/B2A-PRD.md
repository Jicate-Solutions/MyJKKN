## 1. Executive Summary

### What This Is

MyJKKN is currently a **UI-first platform**: 660 pages, 40 service modules, 244 RLS-secured database tables, 326 API routes. All of that institutional intelligence is only accessible to humans navigating a browser.

This PRD specifies the transformation of MyJKKN into a **dual-interface platform** — one where both humans (via UI) and AI agents (via REST API and MCP) can consume the same institutional intelligence. We call this the **B2A (Business-to-Agent) layer**.

### One-Line Summary

> MyJKKN is a B2A platform trapped inside a B2B UI. This document frees the service layer.

### Strategic Thesis

Nicolas Bustamante runs a 6-person company doing what 100+ people did — by routing ALL SaaS through a single AI agent via APIs. Every SaaS becomes an API endpoint for agents. MyJKKN has 40 service modules and 244 tables of institutional intelligence already built. What's missing is the door for agents to walk in.

## 3. Critical Technical Constraint

### The Service Client Mismatch Problem

The 40 existing service modules use `createClientSupabaseClient()` — a **browser client** that requires user cookies + RLS for data scoping.

B2A API-key routes have **no user session**. They must use `createServiceRoleClient()` (from `lib/supabase/server.ts`) which **bypasses all RLS entirely**.

**Consequence:** You CANNOT call existing service classes from B2A routes. Direct queries using the service role client are required.

**Solution strategy:**
- **Phase 1-2:** Write direct queries using service role client (fast, safe)
- **Phase 3+:** Progressively create `*-server.ts` service variants that accept an optional external client

**MANDATORY rule in every B2A query:**
```typescript
// ALWAYS add institution scoping — RLS will NOT protect you
await context.supabase
  .from('any_table')
  .select('*')
  .eq('institution_id', institutionId) // THIS IS MANDATORY
```

## 5. API Key System

### Key Format

```
jkkn_<uuid-without-dashes>
```

Generated by `ApiKeyService.generateKeyValue()`. Stored as SHA-256 hash in `api_keys.key_value`.

### Permission Formats

```json
// Legacy (backward-compatible): all-access
{"read": true, "write": false}

// New (module-scoped):
{"read": ["admission", "attendance", "billing", "grievance", "okr"], "write": []}

// Write-enabled (Phase 3b only):
{"read": ["grievance"], "write": ["grievance"]}
```

### Valid Modules

```
admission | attendance | billing | grievance | okr | learners | staff |
organizations | campus-living | solutions | learners-council | competency |
learning-paths | alumni | facilitator | industry | parent-portal |
social-media | vac | maturity-assessment | process-excellence |
notifications | resource-management | bug-reports | stakeholder-nps | audit-trail
```

### API Key Tiers

| Tier | Permissions | Use Case | TTL |
|------|------------|----------|-----|
| **Viewer** | `read: ['morning-brief']` | Management summary agent | 90 days |
| **Module Reader** | `read: ['admission', 'attendance']` | Dept-specific agent | 30 days |
| **Full Reader** | `read: true` (legacy all-access) | Institutional intelligence agent | 30 days |
| **Writer** | `read: [...], write: ['grievance']` | Phase 3b — selective writes | 7 days |
| **Super** | `read: true, write: true, institution_id: null` | Platform admin ONLY. NEVER for agents. | 24 hours |

### Institution Binding

- If `api_keys.institution_id` is set: key can ONLY access that institution's data
- If `api_keys.institution_id` is NULL: key can access any institution (requires `?institutionId=<uuid>` query param)
- This is enforced at APPLICATION level (not RLS) because service role client bypasses RLS

## 8. Security Requirements

### 5-Layer Application Security Model

Since service role client bypasses RLS, ALL security is at application level:

| Layer | Enforcement Point | Failure Response |
|-------|------------------|-----------------|
| 1. Key validation | `authenticate.ts` — hash lookup, is_active, expiry | 401 UNAUTHORIZED |
| 2. Module scoping | `authenticate.ts` — `permissions.read` check | 403 FORBIDDEN |
| 3. Institution binding | `authenticate.ts` — `institution_id` match | 403 FORBIDDEN |
| 4. Rate limiting | `rate-limiter.ts` — 60 req/min sliding window | 429 RATE_LIMITED |
| 5. Audit logging | `audit-logger.ts` — fire-and-forget | N/A (non-blocking) |

### Security Rules

- **READ-ONLY by default**: Phases 1-4 expose zero write endpoints
- **No super keys for agents**: Never `institution_id = NULL` + `write: true` for automated use
- **No PII in error responses**: Errors return machine-readable codes only
- **`X-Confirm-Write: true`** header required for Phase 3b write endpoints (UX gate, not security gate)
- **Anomaly detection** (recommended): Nightly job comparing usage patterns to baseline

### Known Attack Vectors

| Vector | Risk | Mitigation |
|--------|------|-----------|
| Key theft | Valid key = valid access until expiry | Short TTLs, audit logging |
| Scope escalation | Bug in institution check = cross-tenant leak | Integration test: Institution A key cannot read Institution B data |
| Context Engine bypass | `read: ['attendance']` key uses context query to get billing data | Validate ALL modules in context query against permissions |
| Memory PII exfiltration | Agent writes inferred PII to memory | Validate memory content tags against source module permissions |
| Multi-key rate bypass | 60/min × N keys | Monitor total requests per institution |

## 10. API Response Standards

### Success Response

```json
{
  "data": { ... },
  "meta": {
    "total": 150,
    "page": 1,
    "limit": 20,
    "totalPages": 8,
    "response_time_ms": 234
  }
}
```

### Error Response

```json
{
  "error": {
    "code": "UNAUTHORIZED",
    "message": "API key has expired"
  }
}
```

### Error Codes

| Code | HTTP Status | When |
|------|-------------|------|
| `UNAUTHORIZED` | 401 | Missing/invalid/expired API key |
| `FORBIDDEN` | 403 | Valid key, wrong institution or module |
| `BAD_REQUEST` | 400 | Missing required params (e.g., `institutionId`) |
| `NOT_FOUND` | 404 | Resource does not exist |
| `RATE_LIMITED` | 429 | Exceeded 60 req/min |
| `INTERNAL_ERROR` | 500 | Unexpected server error |
