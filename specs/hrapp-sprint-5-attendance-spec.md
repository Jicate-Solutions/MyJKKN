## 1. Why this exists

JKKN runs on **hrapp.co**, a third-party HR system that generated **1,678 customer-complaint messages** (corpus at `specs/hrapp-issues-capture.md`). 55% of those complaints are attendance-related: false LOPs, missing punches, day-calculation errors, sync delays. Until staff stop getting wrongly marked absent, no MyJKKN HR module is real to them.

**Evidence quotes** (anchoring the design):

## 6. Schema (DDL goes through `supabase/setup/01_tables.sql` + migrations)

```sql
-- 1. Master: status types (per CLAUDE.md value-list rule)
CREATE TABLE hr_attendance_status_types (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  institution_id UUID REFERENCES institutions(id),
  code VARCHAR(20) NOT NULL,         -- 'PRESENT', 'ABSENT', 'HALF_DAY', etc
  label VARCHAR(50) NOT NULL,
  affects_lop BOOLEAN DEFAULT FALSE,
  affects_leave_balance BOOLEAN DEFAULT FALSE,
  is_system BOOLEAN DEFAULT FALSE,
  is_active BOOLEAN DEFAULT TRUE,
  created_at TIMESTAMPTZ DEFAULT NOW(),
  updated_at TIMESTAMPTZ DEFAULT NOW(),
  UNIQUE (COALESCE(institution_id, '00000000-0000-0000-0000-000000000000'::uuid), code)
);

-- 2. Master: regularization reasons
CREATE TABLE hr_regularization_reasons (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  institution_id UUID REFERENCES institutions(id),
  code VARCHAR(30) NOT NULL,
  label VARCHAR(100) NOT NULL,
  is_system BOOLEAN DEFAULT FALSE,
  is_active BOOLEAN DEFAULT TRUE,
  created_at TIMESTAMPTZ DEFAULT NOW(),
  updated_at TIMESTAMPTZ DEFAULT NOW()
);

-- 3. Records: one row per (employee, work_date)
CREATE TABLE hr_attendance_records (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  employee_id UUID NOT NULL REFERENCES hr_employees(id),
  hr_organization_id UUID NOT NULL REFERENCES hr_organizations(id),
  institution_id UUID REFERENCES institutions(id),
  work_date DATE NOT NULL,
  status_type_id UUID NOT NULL REFERENCES hr_attendance_status_types(id),
  in_at TIMESTAMPTZ,
  out_at TIMESTAMPTZ,
  source VARCHAR(20) NOT NULL,  -- ENUM: BIOMETRIC|MANUAL|SELF_MARK|HR_OVERRIDE|CLASS_PROXY|WHATSAPP_CONFIRM
  day_calc VARCHAR(15) DEFAULT 'FULL',  -- ENUM: FULL|HALF_AM|HALF_PM|HOURLY|NONE
  hours_worked NUMERIC(4, 2),  -- for HOURLY day_calc
  reconciled_by UUID REFERENCES profiles(id),
  reconciled_at TIMESTAMPTZ,
  notes TEXT,
  created_at TIMESTAMPTZ DEFAULT NOW(),
  updated_at TIMESTAMPTZ DEFAULT NOW(),
  UNIQUE (employee_id, work_date)
);
CREATE INDEX hr_attendance_records_emp_date ON hr_attendance_records(employee_id, work_date DESC);
CREATE INDEX hr_attendance_records_org_date ON hr_attendance_records(hr_organization_id, work_date DESC);

-- 4. Regularization requests (workflow table)
CREATE TABLE hr_attendance_regularizations (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  employee_id UUID NOT NULL REFERENCES hr_employees(id),
  attendance_record_id UUID REFERENCES hr_attendance_records(id),
  for_date DATE NOT NULL,
  reason_code_id UUID REFERENCES hr_regularization_reasons(id),
  reason_text TEXT,
  proposed_status_type_id UUID REFERENCES hr_attendance_status_types(id),
  proposed_in_at TIMESTAMPTZ,
  proposed_out_at TIMESTAMPTZ,
  status VARCHAR(20) DEFAULT 'pending',  -- pending|approved|rejected|auto_resolved
  approver_id UUID REFERENCES profiles(id),
  approved_at TIMESTAMPTZ,
  rejection_reason TEXT,
  created_at TIMESTAMPTZ DEFAULT NOW(),
  updated_at TIMESTAMPTZ DEFAULT NOW()
);

-- 5. Exceptions (unresolved mismatches needing HR review)
CREATE TABLE hr_attendance_exceptions (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  employee_id UUID REFERENCES hr_employees(id),
  hr_organization_id UUID REFERENCES hr_organizations(id),
  exception_date DATE NOT NULL,
  exception_type VARCHAR(30) NOT NULL,  -- single_punch_day | device_offline | duplicate_punch | mismatched_proxy | unmatched_biometric
  raw_payload JSONB,
  resolution_status VARCHAR(20) DEFAULT 'open',  -- open|resolved|ignored
  resolved_by UUID REFERENCES profiles(id),
  resolved_at TIMESTAMPTZ,
  created_at TIMESTAMPTZ DEFAULT NOW()
);

-- 6. Audit log (who changed what)
CREATE TABLE hr_attendance_audit_log (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  attendance_record_id UUID REFERENCES hr_attendance_records(id),
  actor_id UUID REFERENCES profiles(id),
  action VARCHAR(30) NOT NULL,  -- create|update|override|delete|regularize_approve
  before_state JSONB,
  after_state JSONB,
  reason TEXT,
  created_at TIMESTAMPTZ DEFAULT NOW()
);
```

## 7. The 4-source reconciliation algorithm

For any `(employee_id, work_date)` tuple, attendance is determined by the FIRST applicable source in this priority:

| Priority | Source | Trigger | Day calc |
|---|---|---|---|
| 1 | **HR_OVERRIDE** (manual edit by HR officer) | Explicit row by hr_admin | As specified |
| 2 | **APPROVED_REGULARIZATION** | `hr_attendance_regularizations.status='approved'` | As approved |
| 3 | **BIOMETRIC** (Sprint 4) | eSSL push for that day | Computed from in/out timestamps + work_schedule |
| 4 | **WHATSAPP_CONFIRM** (self-healing step 2) | User replied "REGULARIZE YES" to morning prompt | Inherits from work_schedule defaults |
| 5 | **CLASS_PROXY** (self-healing step 1) | Faculty taught a class on that date per `timetables` + `student_attendance` | FULL (assume present whole day) |
| 6 | **SELF_MARK** | Employee tapped "I'm in" on `/my/attendance` | Single-source: fragile, flagged for HR review |
| 7 | **MANUAL** (HR officer entered without override) | One-time entry | As specified |
| 8 | **default LEAVE** | `hr_leave_applications.status='approved'` covers this date | LEAVE |
| 9 | **default HOLIDAY** | `institution_leaves` covers this date | HOLIDAY |
| 10 | **default ABSENT** | None of above triggered | ABSENT (LOP=true unless override) |

**Hard invariant**: LOP is NEVER the default. ABSENT only fires when 9 prior sources all returned no signal AND no leave/holiday covers the date. This is the literal inverse of hrapp.co's failure mode.

---

## 8. Self-healing: the v4 innovation

When a punch is missing (typically morning, single-entry day), the cron at 18:00 IST runs the 3-step heal:

1. **Class-proxy check**: did this employee teach a class today (per `timetables` + `student_attendance` for the lecturer)? → Auto-mark PRESENT, source=CLASS_PROXY. Done.
2. **WhatsApp confirm**: send "Hi {name}, we couldn't find your morning punch on {date}. Reply YES if you were present." — accept reply within 24h → Auto-mark PRESENT, source=WHATSAPP_CONFIRM. Idempotent webhook.
3. **Shift-end default**: If no class proxy AND no WhatsApp reply in 24h → auto-create `hr_attendance_exceptions` row (single_punch_day) for HR officer review. Status defaults to ABSENT but flagged for exception queue, NOT auto-LOP.

WhatsApp uses existing BYOW infrastructure (per memory `byow-whatsapp.md`). No new vendor onboarding.
