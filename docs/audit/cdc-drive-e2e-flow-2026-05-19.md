## Idempotency Verification

Each notification row uses `idempotency_key = 'cdc.drive.<drive_id>.<to_state>'`. The function uses `ON CONFLICT (idempotency_key) WHERE (idempotency_key IS NOT NULL) DO NOTHING`. Re-running the same UPDATE within the same transaction (or replaying the trigger) produces no duplicates.

## Trigger Function Defense-Layer Audit

Read of `fn_cdc_emit_drive_notification`:

1. **Drive existence guard**: If the drive vanished mid-transaction (unlikely), function returns silently. ✅
2. **Actor fallback chain**: `p_actor` → `NEW.updated_by` → `NEW.created_by` → silent skip if all NULL. This is the gate that initially caught a bare INSERT in our test — drives without `created_by` produce ZERO notifications. ⚠️ Important contract for callers.
3. **Empty-recipient guard**: `IF v_user_ids IS NULL OR array_length(v_user_ids, 1) IS NULL THEN RETURN`. Silent skip when nobody matches. ✅
4. **Idempotency**: Per state via composite key. ✅

## Follow-up Findings (NOT bugs in C1 scope)

### Finding 1 — Profile-mapping gap (44 of 624 learners unreachable)

The `willingness_open` notification fired for **580 recipients** out of **624 learners** in the eligible program (program_id `0d980d34-f945-4de6-8c88-ee97b2620b99`). The gap (44 learners, ~7%) is caused by the function's JOIN:

```sql
SELECT array_agg(DISTINCT p.id) ...
FROM public.profiles p
JOIN public.learners_profiles lp ON lp.id = p.learner_id
JOIN public.cdc_drive_eligibility e ...
```

Learners whose `learners_profiles.id` is NOT referenced by any `profiles.learner_id` (i.e., no auth-user is mapped to their learner record) are silently invisible to the notification path. They will not receive the in-app alert when a drive opens for willingness.

**Recommended follow-up**: audit `learners_profiles` rows without a matching `profiles.learner_id`; either backfill the profile link or document this as an expected gap (e.g., for learners who never logged in).

### Finding 2 — Contract: `cdc_drives.created_by` must be set

When the drive's `created_by` is NULL and `updated_by` is also NULL, the trigger silently no-ops on every transition. Sprint 2 dispatcher must always populate at least one of these. Verified during initial test (zero notifications until `created_by` was set).

**Recommended follow-up**: add a `NOT NULL` constraint on `cdc_drives.created_by`, or a `CHECK` ensuring at least one of `created_by`/`updated_by` is non-null on every transition.
