# Admission CRM Enhancement — Full Roadmap Specification

> Generated by SDD workflow on 2026-04-08
> Source: NeoDove competitive analysis + MyJKKN codebase audit
> Scope: 10 learnings → 6 phased features (prioritized by impact/effort)

## Overview

Enhance the existing MyJKKN Admission CRM to close key UX and architectural gaps identified from NeoDove's EdTech telecalling CRM. The CRM already has deep data capabilities (77 hooks, 44 services, 5 communication channels, 29 funnel stages, AI scoring). The enhancement focuses on **counselor productivity UX**, **integration connectivity**, and **real-time operational visibility** — the three areas where NeoDove outperforms us.

**Who:** Admission counselors (primary), admission managers/admins (secondary), super_admin (oversight)
**What:** 6 features that make the existing CRM more usable, connected, and observable
**Why:** Counselors currently use 5+ different pages to work a single lead. NeoDove lets counselors do everything from one screen. Our data is richer; their UX is better. We're bridging that gap.

## Functional Specification

### User Roles

| Role | Can Do | Cannot Do |
|------|--------|-----------|
| **counselor** | View/work assigned leads, make calls, send messages, dispose calls, view own KPIs | See other counselors' KPIs, manage integrations, access admin settings |
| **admin** | Everything counselor can + view all counselor KPIs, manage integrations, configure webhook sources, view team dashboards | Access other institutions' data |
| **super_admin** | Everything admin can + cross-institution view, all settings | N/A |

### Feature 1: Log Call — Prominent Post-Call Disposition Dialog

**Priority:** DO FIRST | **Impact:** Very High | **Effort:** Low

> **INTERVIEW CORRECTION (2026-04-08):** Original spec assumed Exotel click-to-call as primary flow. Reality: counselors call from their **personal phones** and then manually log the outcome in MyJKKN. The `FloatingCallBar` only activates for Exotel calls (rarely used). The real need is a **prominent "Log Call" button** — the #1 action on the lead detail page.

**Status of existing:** `FloatingCallBar` exists for Exotel calls (keep it). But no quick "Log Call" action for the primary flow (personal phone calls).

#### What We're Building

A **"Log Call" dialog** that is:
- The **most prominent button** on the lead detail page (primary CTA position)
- Also the **first action** on the mobile counselor screen (Feature 6)
- Designed for speed — counselor just hung up, wants to log in 15 seconds

#### Screen: Log Call Dialog

- **Location:** Opens as a dialog/sheet from the lead detail page
- **Trigger:** Big "Log Call" button at top of lead detail (in Quick Actions bar)
- **Who sees it:** Any user viewing a lead

```
┌─────────────────────────────────────────────────┐
│ 📞 Log Call — Raj Kumar                    [X]  │
├─────────────────────────────────────────────────┤
│                                                 │
│ Did they pick up?                               │
│ [✅ Connected]  [❌ Not Answered]  [📵 Busy]   │
│ [❓ Wrong Number]  [📞 Voicemail]              │
│                                                 │
│ ─── If Connected ───────────────────────────── │
│                                                 │
│ Interest Level:                                 │
│ [🔥 Hot]  [🌡️ Warm]  [❄️ Cold]  [👎 Not Int.] │
│                                                 │
│ What's the next step?                           │
│ [▼ Send Brochure / Schedule Visit / Refer HOD / │
│    Follow Up / No Action Needed]                │
│                                                 │
│ Notes: [___________________________________]    │
│                                                 │
│ Follow-up: [Date picker] [Time picker]          │
│                                                 │
│ Stage: [New] → Suggest: [Contacted ✓]           │
│                                                 │
│     [Save & Close]  [Save & Send WhatsApp →]    │
└─────────────────────────────────────────────────┘
```

**Actions on Save:**
1. Create new `admission_call_logs` record (direction: outbound, status: completed, logged manually)
2. Update `admission_leads.last_contact_at` to now
3. If follow-up set → update `admission_leads.next_followup_at` + auto-create reminder
4. If stage change accepted → update `admission_leads.funnel_stage`
5. Log activity via `activity-service` (type: 'call')
6. If "Save & Send WhatsApp" → open `SendPersonalMessageDialog` pre-filled with template
7. Invalidate all related queries (timeline, call stats, funnel summary)

**Key Design Principle:** No required fields except "Did they pick up?" — counselors must be able to log in 3 taps: Connected → Hot → Save. Everything else is optional.

**Edge Cases:**
- What if lead doesn't have a phone? → Shouldn't happen (phone required), but show "No phone on record"
- What if counselor accidentally logs twice? → Show "You logged a call 2 minutes ago — log another?" confirmation
- What if counselor is not the assigned counselor? → Still works, but `counselor_id` on the call log = current user, not assigned counselor
- What if dialog is opened on mobile? → Must be full-screen sheet on mobile (not a centered dialog)

**FloatingCallBar:** Keep as-is for the rare Exotel click-to-call usage. No changes needed.

### Feature 4: Generic Inbound Lead Webhook, Agent Referral Form & Integration Dashboard

**Priority:** DO FOURTH | **Impact:** Very High | **Effort:** Medium
**Status of existing:** 2 webhooks (WhatsApp personal + calls bulk-callback). 12 source labels. No generic inbound endpoint. No integration UI.

> **INTERVIEW CORRECTION (2026-04-08):** Biggest lead leak is **agent/consultant referrals** — agents send leads via WhatsApp messages and phone calls to admission office. These often don't get logged. In addition to the API webhook, we need a **simple Agent Referral Form** — a public URL agents can bookmark and submit leads in 30 seconds from their phone. No login required.

#### Screen: Agent Lead Referral Form (PUBLIC — no login)

- **URL:** `/refer?institution=JKKN` (public route, no auth)
- **Who uses it:** External agents/consultants on their mobile phones
- **Purpose:** Replace "WhatsApp a counselor" with a 30-second form submission

```

│ 🎓 JKKN — Refer a Student   │
│                              │
│ Student Name: [____________] │
│ Phone*:       [____________] │
│ Email:        [____________] │
│ Program:      [▼ dropdown  ] │
│ Your Name*:   [____________] │
│ Your Phone*:  [____________] │
│ Notes:        [____________] │
│                              │
│     [Submit Referral]        │
│                              │
│ ✅ Referral submitted!       │
│ Reference: JKKN-REF-00234    │
└──────────────────────────────┘
```

**Processing:**
1. No login — public form submission
2. Validates phone (required), agent name (required), agent phone (required)
3. Creates lead via `lead-service.createLead()` with `source: 'agent'`, `referral_type: 'consultant'`, `referred_by_name`, `referred_by_id` (if agent is in consultants table)
4. Deduplicates by phone number
5. Auto-assigns via assignment rules
6. Sends confirmation to agent (WhatsApp or SMS if configured)
7. Returns reference number for tracking

**Edge Cases:**
- Agent submits same student twice → "This student is already in our system (Ref: JKKN-REF-00123)"
- Agent is not in consultants table → Create lead anyway, flag for admin review
- Form spam → Rate limit: 10 submissions per IP per hour + honeypot field

#### API: Generic Inbound Webhook

- **URL:** `POST /api/admission/leads/inbound`
- **Auth:** API key (from `api_keys` table) OR HMAC signature
- **Purpose:** Accept leads from ANY external source

**Request body (flexible):**
```json
{
  "source": "facebook_ads",
  "source_id": "fb-campaign-april-2026",
  "name": "Raj Kumar",
  "phone": "9876543210",
  "email": "raj@example.com",
  "interested_program": "B.Tech CSE",
  "custom_fields": {
    "fb_lead_id": "123456",
    "ad_name": "April Intake Campaign"
  }
}
```

**Processing:**
1. Validate API key → get `institution_id`
2. Deduplicate by phone (check existing leads)
3. Map fields via `admission_integration_field_mappings` config
4. Create lead via `lead-service.createLead()`
5. Apply assignment rules via `assignment-rules-service`
6. Log to `admission_integration_logs` table
7. Return `{ success: true, lead_id: "...", is_duplicate: false }`

#### Data Model: New Tables

**`admission_integrations`**
| Column | Type | Purpose |
|--------|------|---------|
| id | uuid (PK) | |
| institution_id | uuid (FK) | Multi-tenant |
| name | text | Display name ("Facebook Lead Ads - April") |
| type | enum | facebook_ads, google_sheets, webhook, justdial, indiamart, shiksha, collegedunia, custom_api |
| config | jsonb | Type-specific config (API keys, sheet ID, webhook secret) |
| field_mapping | jsonb | Maps external field names to admission_leads columns |
| is_active | boolean | Enable/disable |
| last_sync_at | timestamptz | Last successful lead received |
| total_leads | integer | Counter |
| created_at, updated_at | timestamptz | |

**`admission_integration_logs`**
| Column | Type | Purpose |
|--------|------|---------|
| id | uuid (PK) | |
| integration_id | uuid (FK) | Which integration |
| institution_id | uuid (FK) | |
| lead_id | uuid (FK, nullable) | Created/matched lead |
| raw_payload | jsonb | Original request body |
| status | enum | success, duplicate, validation_error, error |
| error_message | text (nullable) | |
| created_at | timestamptz | |

#### Edge Cases:
- What if phone number already exists? → Return `is_duplicate: true` with existing `lead_id`. Don't create new lead. Optionally merge new fields.
- What if required field missing? → Return 400 with field-level errors: `{ errors: [{ field: "phone", message: "required" }] }`
- What if rate limit exceeded? → 429 with retry-after header (100 leads/min per integration)
- What if integration is disabled? → 403 "Integration is not active"

## Technical Plan

See full implementation plan: `docs/plans/2026-04-08-admission-crm-enhancement.md`

### Architecture Summary

| Layer | What Changes |
|-------|-------------|
| **Database** | 3 new columns on `admission_call_logs` (outcome, interest, next_action) + 2 new tables (`admission_integrations`, `admission_integration_logs`) |
| **Services** | 3 new services (integration, counselor-productivity, stage-suggestions utility) + 1 modified (telephony) |
| **Hooks** | 4 new hooks (integrations, productivity, lead-work-queue) + 1 modified (call-mutations) |
| **API Routes** | ~8 new routes (inbound webhook, integrations CRUD, productivity) + 1 modified (call notes) |
| **Pages** | 3 new pages (integrations settings, productivity dashboard, mobile work view) + 2 modified (lead detail, lead list) |
| **Components** | 1 modified (FloatingCallBar) + ~12 new components (quick actions bar, source badges, mobile cards, etc.) |

### Key Technical Decisions

| Decision | Chosen | Alternative | Why |
|----------|--------|-------------|-----|
| Stage suggestion | Client-side utility function | Server-side AI scoring | Simpler, deterministic, no latency. Can upgrade to AI later. |
| Campaign tags | Query `campaign_queue` table | Dedicated junction table | Avoid schema changes; campaign_queue already links leads to campaigns |
| Inbound webhook auth | Reuse existing `api_keys` table via `withAuth` | New webhook secrets table | Consistent with existing auth pattern, less code |
| Productivity data | Direct SQL queries with date filters | Materialized view / pre-aggregation | Real-time accuracy > query speed for <50 counselors |
| Mobile UI | Responsive web page with scroll-snap | React Native / PWA shell | No new tooling; works in mobile Chrome immediately |
