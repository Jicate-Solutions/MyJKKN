> Generated by SDD workflow on 2026-04-05
> Updated: 2026-04-05 — Revised after production codebase audit (Jicate-Solutions/MyJKKN main)
> Source: `docs/exotel-api-reference.md` (93 endpoints inventoried)

## Overview

Expand MyJKKN's Exotel integration from 4 API endpoints to a comprehensive admission communication platform. Several capabilities already exist in production and need Exotel API wiring rather than building from scratch.

**Who:** Admission counselors and managers at JKKN Institutions
**What:** 10 capabilities — 5 genuinely new, 3 enhance existing, 2 connect existing services to Exotel APIs
**Why:** 72% of incoming calls go unanswered. Auto-transcription eliminates manual notes. Connecting existing campaign/WhatsApp infrastructure to Exotel's native APIs adds bulk operations, scheduling, and analytics.

## Capability 1: ExoVoiceAnalyze — Call Transcription & Sentiment (BUILD NEW)

### True Goal
Automatically transcribe every answered call, extract sentiment, generate summaries, and categorize by inquiry type — eliminating manual call notes and enabling counselor quality monitoring.

### User Flow
1. Counselor finishes a call (or inbound call ends with cost_amount > 0)
2. System automatically POSTs to ExoVoiceAnalyze API with the call_sid
3. Exotel processes async → delivers results to our webhook (30s-5min)
4. Webhook stores transcription, sentiment, summary, category in DB
5. Call detail page shows transcription tab with all intelligence
6. Dashboard shows sentiment trends per counselor

### Screens

#### Call Detail Page — Transcription Tab (NEW)
- **URL:** `/admission/counselors/calls/[id]` (new tab)
- **Shows:** Full transcription (speaker-separated), sentiment badge (Positive/Neutral/Negative), auto-summary (2-3 sentences), category tags
- **Actions:** Re-analyze button (re-submit to ExoVoiceAnalyze), copy transcript
- **Edge cases:** Analysis pending (show spinner + "Transcribing..."), analysis failed (show retry button), no recording URL (show "No recording available")

#### Counselor Performance — Sentiment Column (ENHANCED)
- **URL:** `/admission/counselors/calls` (existing table)
- **Shows:** Sentiment icon per call row (green/yellow/red dot)
- **Edge cases:** Not yet analyzed (gray dot), analysis failed (dash)

### Data Model

```sql
CREATE TABLE admission_call_intelligence (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  call_log_id UUID NOT NULL REFERENCES admission_call_logs(id) ON DELETE CASCADE,
  institution_id UUID NOT NULL REFERENCES institutions(id),
  analysis_job_id TEXT,
  status TEXT DEFAULT 'pending' CHECK (status IN ('pending', 'processing', 'completed', 'failed')),
  transcription TEXT,
  transcription_segments JSONB DEFAULT '[]',
  sentiment TEXT CHECK (sentiment IN ('positive', 'neutral', 'negative', 'mixed')),
  sentiment_score NUMERIC(4,2),
  summary TEXT,
  categories TEXT[] DEFAULT '{}',
  language_detected TEXT,
  error_message TEXT,
  analyzed_at TIMESTAMPTZ,
  created_at TIMESTAMPTZ DEFAULT NOW()
);

CREATE INDEX idx_call_intelligence_call ON admission_call_intelligence(call_log_id);
CREATE INDEX idx_call_intelligence_status ON admission_call_intelligence(status);
CREATE INDEX idx_call_intelligence_sentiment ON admission_call_intelligence(sentiment);
CREATE UNIQUE INDEX idx_call_intelligence_job ON admission_call_intelligence(analysis_job_id) WHERE analysis_job_id IS NOT NULL;
```

### API Routes

| Method | Path | Purpose |
|--------|------|---------|
| POST | `/api/admission/calls/[id]/analyze` | Trigger ExoVoiceAnalyze for a call |
| GET | `/api/admission/calls/[id]/intelligence` | Get transcription + sentiment + summary |
| POST | `/api/webhooks/telephony/voice-analyze` | Receive ExoVoiceAnalyze async results |

### ExotelClient Method

```typescript
static async analyzeCall(callSid: string, tasks: ('transcript' | 'sentiment' | 'summarization' | 'categorise')[], callbackUrl: string): Promise<{ job_id: string }>
```

### Assumptions
- [A1-1] ExoVoiceAnalyze is in alpha — may have reliability issues. Store job_id for retry.
- [A1-2] Results arrive async via webhook, typically 30s-5min after submission.
- [A1-3] Auto-analyze only answered calls (cost_amount > 0). Manual trigger for any call.
- [A1-4] Categories: fee_inquiry, course_inquiry, admission_process, complaint, follow_up, general, placement, hostel, scholarship, other.

## Capability 2: Bulk SMS (ENHANCE EXISTING)

### True Goal
Add Exotel's bulksend endpoint to the existing `SMSCampaignService` so batch SMS sends use one API call per 100 messages instead of looping single sends.

### Production Baseline
- `lib/services/admission/sms-campaign-service.ts` exists with `sendBulkSMS()` method
- Current `sendBulkSMS()` loops `sendCampaignSMS()` for each lead — slow, fragile
- Supports MSG91, Twilio, Exotel providers via `NEXT_PUBLIC_SMS_PROVIDER`
- `admission_sms_logs` table exists with all needed columns

### What to Change
1. Add `ExotelClient.sendBulkSms(messages[])` — POST to `/v1/Accounts/{sid}/Sms/bulksend`
2. Update `SMSCampaignService.sendBulkSMS()` — when provider is 'exotel', use bulksend instead of loop
3. Handle HTTP 207 response — per-message status parsing

### No New Tables Needed
Uses existing `admission_sms_logs` table.

### Assumptions
- [A2-1] Max 100 messages per API call (Exotel limit). Service splits larger batches.
- [A2-2] DLT entity_id and template_id already handled by existing SMS service.
- [A2-3] Delivery status via existing SMS webhook (`/api/webhooks/sms?provider=exotel`).

## Capability 3: Voice v3 Upgrade (BUILD NEW)

### True Goal
Upgrade from Exotel Voice v1 to v3 for dual-channel recording, call leg visibility, and agent state management.

### What to Change
1. Add `EXOTEL_CCM_SUBDOMAIN` env var (feature flag — v1 fallback if not set)
2. Add `ExotelClient.makeCallV3()`, `getCallDetailsV3()`, `getCallLegs(callSid)`
3. New `admission_call_legs` table for leg data
4. Update `TelephonyService.initiateCall()` — use v3 when CCM configured
5. Update webhook handler — parse v3 format (assigned_agent_details, call_state)

### Data Model

```sql
CREATE TABLE admission_call_legs (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  call_log_id UUID NOT NULL REFERENCES admission_call_logs(id) ON DELETE CASCADE,
  leg_id TEXT NOT NULL,
  leg_type TEXT NOT NULL CHECK (leg_type IN ('from', 'to')),
  phone_number TEXT,
  status TEXT,
  duration_seconds INTEGER,
  recording_url TEXT,
  recording_channel TEXT CHECK (recording_channel IN ('single', 'dual')),
  started_at TIMESTAMPTZ,
  answered_at TIMESTAMPTZ,
  ended_at TIMESTAMPTZ,
  created_at TIMESTAMPTZ DEFAULT NOW()
);

CREATE INDEX idx_call_legs_call ON admission_call_legs(call_log_id);
```

### Assumptions
- [A3-1] Feature-flagged: only activates if `EXOTEL_CCM_SUBDOMAIN` is set.
- [A3-2] v1 continues working as fallback. No breaking changes.
- [A3-3] CCM subdomain: `ccm-api.in.exotel.com` (different from `api.in.exotel.com`).

## Capability 4: Call Campaigns — Wire Existing (WIRE EXISTING)

### True Goal
Connect the existing `VoiceBroadcastService` to Exotel's Campaign API (v2) so campaigns actually dial contacts through Exotel instead of being data-only.

### Production Baseline
- `VoiceBroadcastService` — full CRUD: create/update/delete/start/pause/cancel + logs + stats
- `use-voice-broadcast.ts` + `use-voice-agents.ts` hooks
- `/admission/marketing/voice-agents/page.tsx` exists
- **Missing:** No Exotel Campaign API calls — service manages local data only

### What to Change
1. Add `ExotelClient` methods: `createCampaign()`, `getCampaign()`, `updateCampaign()`, `listCampaigns()`, `getCampaignCallDetails()`
2. Wire `VoiceBroadcastService.startCampaign()` → call `ExotelClient.createCampaign()` with contact list + schedule
3. Wire `VoiceBroadcastService.pauseCampaign()` / `cancelCampaign()` → Exotel PUT with action
4. Add webhook: `/api/webhooks/telephony/campaign-status` for Exotel campaign callbacks
5. Add webhook: `/api/webhooks/telephony/campaign-call` for per-call results
6. Store `exotel_campaign_id` in existing broadcast campaigns table

### No New Tables
Add `exotel_campaign_id TEXT` column to existing broadcast campaigns table.

### Assumptions
- [A4-1] Max 5000 contacts per campaign (Exotel limit).
- [A4-2] Calling hours default 9 AM - 6 PM IST.
- [A4-3] Exotel Campaign API uses v2: `POST /v2/accounts/{sid}/campaigns`

## Capability 8: WhatsApp via Exotel (EVALUATE — LIKELY SKIP)

### Production Reality
MyJKKN production already has a **comprehensive WhatsApp integration** using Meta's Cloud API directly:

- **19 service files** under `lib/services/whatsapp/`
- Chat service, API client, connection management, consent tracking, document catalog, forms, message logging, personal messaging, auto-triggers, queue management, templates, re-engagement, routing, segments, settings, template analytics, counselor analytics
- **DB tables:** `wa_conversations`, `wa_messages`, `admission_whatsapp_logs`
- **Webhook:** `/api/webhooks/whatsapp/route.ts`
- **Hooks:** `use-whatsapp-campaign.ts`, `use-whatsapp-personal.ts`

### Recommendation
**Skip C8.** The existing Meta Cloud API integration is far more mature than what Exotel WhatsApp would provide. Exotel WhatsApp would be a downgrade. Only revisit if:
- Exotel offers significantly lower per-message pricing
- Need unified billing across voice + SMS + WhatsApp through one vendor
- Meta API access issues arise

## Capability 9: Number Masking — GreenVN (BUILD NEW)

### Data Model

```sql
CREATE TABLE admission_number_masks (
```
