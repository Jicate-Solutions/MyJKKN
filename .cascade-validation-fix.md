# Cascading Validation Fix for Bulk Upload

## Problem
The validation system was validating academic fields independently without context, leading to:
- `institutionId` being undefined in queries
- Semester queries not filtering by program (returning 0 or wrong results)
- Section queries not filtering by semester (returning 242 rows for "A" instead of specific section)

## Solution: Cascading Validation with Context

### 1. Modified `extractUniqueValues()` in `lib/utils/bulk-upload-validation.ts`
**Before:** Extracted unique values independently
```typescript
{
  programs: ["CSE"],
  semesters: ["II YEAR III SEMESTER"],
  sections: ["A"]
}
```

**After:** Extracts hierarchical values with context
```typescript
{
  programs: ["CSE"],
  semestersWithContext: [
    { program: "CSE", semester: "II YEAR III SEMESTER" }
  ],
  sectionsWithContext: [
    { program: "CSE", semester: "II YEAR III SEMESTER", section: "A" }
  ]
}
```

### 2. Updated `BulkValidationBatchService.validateBatch()`
**Cascading Flow:**
1. **Step 1:** Validate Programs with `institutionId`
   - Stores results in Map with key = program name

2. **Step 2:** Validate Semesters with `institutionId` + `programId`
   - Gets programId from Step 1 results
   - Stores results with composite key = `"PROGRAM|SEMESTER"`

3. **Step 3:** Validate Sections with `institutionId` + `semesterId`
   - Gets semesterId from Step 2 results
   - Stores results with composite key = `"PROGRAM|SEMESTER|SECTION"`

### 3. Updated `getDatabaseValidationErrors()`
**Changed lookup keys:**
```typescript
// Before
const semResult = validationResult.semesters[data.semester_name];
const secResult = validationResult.sections[data.section_name];

// After
const semesterKey = `${data.program_name}|${data.semester_name}`;
const semResult = validationResult.semesters[semesterKey];

const sectionKey = `${data.program_name}|${data.semester_name}|${data.section_name}`;
const secResult = validationResult.sections[sectionKey];
```

## How It Works Now

### Example Validation Flow:
**Excel Row:** Program=CSE, Semester=I YEAR I SEMESTER, Section=A

1. **Validate Program "CSE"**
   - Query: `SELECT * FROM programs WHERE program_name ILIKE 'CSE' AND institution_id = ?`
   - Result: `{ id: "prog-123", found: true }`
   - Stored as: `programs["CSE"]`

2. **Validate Semester "I YEAR I SEMESTER" for Program "CSE"**
   - Gets programId from `programs["CSE"].id` = "prog-123"
   - Query: `SELECT * FROM semesters WHERE semester_name ILIKE 'I YEAR I SEMESTER' AND institution_id = ? AND program_id = 'prog-123'`
   - Result: `{ id: "sem-456", found: true }`
   - Stored as: `semesters["CSE|I YEAR I SEMESTER"]`

3. **Validate Section "A" for CSE / I YEAR I SEMESTER**
   - Gets semesterId from `semesters["CSE|I YEAR I SEMESTER"].id` = "sem-456"
   - Query: `SELECT * FROM sections WHERE section_name ILIKE 'A' AND institution_id = ? AND semester_id = 'sem-456'`
   - Result: `{ id: "sec-789", found: true }` (returns 1 row, not 242!)
   - Stored as: `sections["CSE|I YEAR I SEMESTER|A"]`

## Benefits
✅ **Accurate Validation:** Sections now filtered by their actual semester (not all sections named "A")
✅ **Better Suggestions:** Suggestions are context-aware (e.g., semesters for CSE program only)
✅ **Performance:** Still uses batch validation, just with proper context
✅ **Scalability:** Works with any hierarchy depth
