## Decisions Made

### 1. Target Users
- **Decision:** 40 management users (not 10,000 general users)
- **Rationale:** Start with high-value users to prove concept, scale later
- **Users:** Director, Principals, VPs, Department Heads, Finance, Admission, HR

### 2. Access Model
- **Decision:** Three-tier access (Director > Principals > VPs/Heads)
- **Rationale:** Role-scoped data prevents information overload
- **Implementation:** Leverage existing MyJKKN roles and institution_id

### 3. Privacy Model
- **Decision:** Director sees all conversations, others see only their own
- **Rationale:** Full transparency with appropriate hierarchy
- **Implementation:** Add user_id filter with Director override

### 4. AI Model Strategy
- **Decision:** Hybrid approach (Claude for complex, cheaper model for simple)
- **Rationale:** Balance quality and cost
- **Implementation:** Intent classifier routes to appropriate model

### 5. Response Time
- **Decision:** Up to 5 minutes acceptable for complex queries (async)
- **Rationale:** Thoroughness over speed for management insights
- **Implementation:** Progress updates + notification when done

### 6. Daily Briefing
- **Decision:** 6 AM delivery via in-app notification
- **Content:** Yesterday's metrics, vs targets, anomalies, predictions
- **Scope:** Role-specific (each role sees their domain)

### 7. Predictions
- **Decision:** Four prediction types enabled
  1. Attendance trajectory
  2. Fee collection risk
  3. Admission shortfall
  4. Staff burnout
- **Rationale:** Proactive > reactive management

### 8. One-Click Actions
- **Decision:** Four action types enabled
  1. Send notifications (in-app)
  2. Generate reports (PDF)
  3. Schedule meetings
  4. Create follow-up tasks
- **Rationale:** Bridge from insight to action

### 9. Uncertainty Handling
- **Decision:** Ask for clarification when data incomplete
- **Rationale:** Accuracy over speed
- **Implementation:** Explicit prompt for user decision

### 10. Benchmarking
- **Decision:** Triple benchmark system
  1. vs internal targets
  2. vs historical (same period last year)
  3. vs peer average
- **Rationale:** Context-rich comparisons

### 11. Alert Thresholds
- **Decision:** Configurable by admin only
- **Rationale:** Centralized control during initial deployment
- **Implementation:** Admin settings panel

### 12. Source Citation
- **Decision:** Show on request (not by default)
- **Rationale:** Clean output with verifiability available
- **Implementation:** "Show Sources" button on each response

### 13. Language
- **Decision:** Respond in user's language (multilingual)
- **Rationale:** Diverse management team
- **Implementation:** Detect input language, respond accordingly

### 14. Device Access
- **Decision:** Both desktop and mobile equally important
- **Implementation:** Responsive design, mobile-optimized UI

### 15. Onboarding
- **Decision:** Suggested prompts (learn by example)
- **Implementation:** Role-specific prompt suggestions in UI

### 16. Fallback
- **Decision:** Direct to dashboards when AI unavailable
- **Rationale:** Graceful degradation
- **Implementation:** Error handler redirects to relevant dashboard

### 17. Audit Trail
- **Decision:** Full audit trail (queries, data, reasoning, timestamps)
- **Rationale:** Compliance and debugging
- **Implementation:** Log every interaction to audit table

### 18. Feedback System
- **Decision:** Thumbs up/down + star rating + flag wrong + comments
- **Rationale:** Multiple feedback channels for learning
- **Implementation:** UI elements on each response

### 19. Cost Tracking
- **Decision:** Admin + Director visibility, per-user tracking, budget alerts
- **Rationale:** Monitor and optimize spend
- **Implementation:** Cost tracking dashboard

### 20. Risk Tolerance
- **Decision:** High tolerance for occasional false alarms
- **Rationale:** System will be tuned over time
- **Implementation:** Learn from feedback loop

### 21. Naming
- **Decision:** "JKKN Assistant"
- **Rationale:** Simple, institutional branding

## Risk Mitigation Plan

**Primary Risk:** Wrong information leading to bad decisions

**Mitigations:**
1. Show sources on request
2. Automatic context checking (holidays, events)
3. Ask for clarification when uncertain
4. User feedback loop
5. Admin review queue
6. Weekly error analysis
